## Project overview
**Project name** (60 max): `Ctrl+A11y: paste a URL, get an accessible site` (46)

**Elevator pitch** (200 max, 180 used):
`Paste any URL. An AI agent finds the accessibility barriers, fixes them, and proves every fix by re-running the same checker, so blind and keyboard users can actually use the page.`

## Project details: About the project

### Inspiration
The WebAIM Million 2026 checked the home pages of the top million websites and found 56.1 accessibility
errors per page on average. More than half have images a blind person can't hear about, and 84% have text
too faint to read. Checkers that list these problems already exist, and the page stays broken. Overlay
widgets that promise to fix them are criticised by blind users for guessing and fighting their screen
readers. We wanted the Ctrl+V of accessibility: paste a page, get it back usable, with proof.

### What it does
- **Check, fix, re-check.** Paste an address (or press Ctrl+V anywhere on our page). Ctrl+A11y opens it in a
  real browser, runs axe-core, the standard accessibility checker, fixes what it can, and runs the same check
  again. A fix counts only if the same rule no longer flags the same element.
- **Fixes the six most common failures** found by the WebAIM Million: low contrast text, missing image
  descriptions, missing form labels, empty links, empty buttons, missing page language, plus page titles,
  landmarks, tab order, invalid ARIA roles and links that rely on colour. Content outside every landmark that
  has its own heading becomes a section screen-reader users can jump to, named after that heading.
- **Says where every fix came from**, in plain language: "Name added: Search, from its icon class",
  "Description added: Goa from Rs 2,999, from the text inside the image". When there is no honest clue, it
  says so and leaves it for a person. An optional vision AI model can describe images that have no clue at all.
- **Never leaves a page worse.** If the re-check finds any new problem, the engine undoes fixes one kind at a
  time until no new problem remains, and reports what it rolled back.
- **Ship it today.** Site owners download one script with only the proven fixes and add one line to their page.
- **Fix pages as you browse.** People who use screen readers add one bookmark; on any hard page it applies the
  proven fixes and announces how many it applied.
- **Works on real, messy sites:** strict security policies, carousels and tickers that change on every load,
  content that appears seconds late. A fresh unfixed copy is checked the same way, so the page's own changes
  are never blamed on a fix, and problems a related fix also cleared are reported as "also resolved".
- **For teams:** WCAG success criterion and severity on every problem, a dated printable report, a check of up
  to 5 more pages of the same site, before/after screenshots, and a CI mode that fails the build when too many
  problems remain.

### How we built it
Python, Playwright and Chromium for a real browser; axe-core 4.10.2 for checking; FastAPI for the app; plain
HTML, CSS and JavaScript for the interface; an optional vision AI model for images with no clue on the page.
The fixers are plain code, so the same page always gets the same fix. Tests check both planted demo pages, the
fix script, the safety net (by sabotaging a fixer on purpose) and the server's safety rules on every push in
GitHub Actions. A benchmark script writes every number we show into CSV files. Even the demo video is
generated by code from the real app.

### Results
- **Demo pages:** 10 of 10 problems fixed and proven, and 12 of 12 on a second page, 0 new problems, no AI model.
- **6 real public pages, AI off** (`results/bench.csv`): 533 problems before, 93 after, 401 fixes proven
  and 39 more resolved as a side effect (proven by the same re-check), 0 that failed the re-check, 0 rolled
  back, 0 new problems. Python.org went from 112 to 2; Hacker News from
  248 to 1.
- **7 Indian sites, AI off** (`results/bench_india.csv`): MyGov, myScheme, DigiLocker, The Hindu, IIT Bombay,
  VTU and Flipkart. 563 problems before, 315 after, 244 fixes proven, 11 more resolved, 0 that failed the re-check,
  0 new problems; the safety net rolled back 1 fix each on MyGov and Flipkart. myScheme, the government's scheme
  finder: 29 to 0. The Hindu: 123 to 28. DigiLocker: 55 to 15.
- **Whole site** (`results/site_news_ycombinator_com.csv`): 6 Hacker News pages, 1,361 problems down to 6.
- **The fix script alone** (`results/fix_script_proof.csv`, `python proof.py`): on fresh, untouched copies,
  Hacker News 248 to 1, python.org 112 to 2 and our demo page 10 to 1, exactly what the engine measured.
- **Our own page:** 0 problems on our own check, desktop and phone, checked in CI on every push.
- **Honest gaps:** two government sites served "Access Denied" to automated browsers, so we report them as not
  scored. Heading order and content outside any clearly named section still need a person.

### Challenges we ran into
- Making "fixed" mean something: we re-run the checker and match each fix to the exact element instead of
  trusting our own fix.
- A fix can make a page worse: our first landmark fixer marked a heading as the main area on a block page. We
  built the automatic rollback, then tested it by sabotaging a fixer on purpose.
- Rotating slideshows: their text is measured mid-fade, so a contrast fix can't be proven. We list it for a
  person instead of claiming it.
- Sites that block automated browsers: we detect the block page and report it instead of scoring it.
- Pages that change on every load (carousels, tickers, random ids): our first safety net undid good fixes on
  MyGov because the reloaded page looked "new". We now load a fresh unfixed copy to tell the page's own changes
  from ours, and wait for late content before checking. That also fixed three real mistakes it exposed: naming
  a button hidden with role=presentation, a main area that swallowed the header, and a second footer.
- Not guessing: every name comes from a real clue on the page, and we show which one.

### Accomplishments that we're proud of
- Not an overlay: no widget, no toolbar, no tracking, only the same attribute fixes a developer would make.
- Zero new problems and zero failed re-checks across every page we measured.
- A blind user can fix a page for themselves with one bookmark, and hear that it worked.
- Our own page passes our own check, and so does the report it generates.

### What we learned
- **A fix you can't prove isn't a fix.** Our first rollback undid good fixes on MyGov because a carousel looked
  different on every load; separating the page's own changes from ours taught us more than any passing test.
- **Checkers disagree with intuition.** Removing a broken `role="tree"` fixed more problems than adding anything,
  and naming a hidden carousel button created new ones. Less ARIA is often the accessible answer.
- **Real sites are messy in ways demo pages never are:** strict security policies, pages that redirect mid-check,
  content that appears seconds after load, and sites that block automated browsers. Each one became a test.
- **Our own page had to pass first.** Building to zero problems on our own check, in CI, kept us honest about what
  we asked other sites to do.

### What's next
- Turn proven fixes into a pull request on the site's own source code, alongside the script.
- Whole-site crawls beyond 5 pages, PDFs, and pages behind a login.
- Descriptions in the user's own language.
